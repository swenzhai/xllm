当前开发自测：官方精度35/35，扩展206/206，全部10个绝对性能case在5个新进程批次均通过；10个分配器内存检查通过。三个XLSX各保留全部35个Case ID及原主表/完整统计格式，非performance的25项性能/内存依任务书3.5标不适用。报告采用最新真实截图批次，逐项数值及复测范围见《补充测试记录》。源码固定提交 `8ea9affaf131b22c8fb786b79da5968ce6724744`，仓库[swenzhai/xllm](https://github.com/swenzhai/xllm/commit/8ea9affaf131b22c8fb786b79da5968ce6724744)，交付分支 `t5-qkv-task-submission`；后续附件提交与被测源码提交区分。

## 环境及前置配置

实测Ascend910_9382（A3/910C）、CANN9.1.0、Ubuntu22.04.5、driver26.1.1、Python3.12.13、torch2.10.0+cpu、torch_npu2.10.0.post4、NumPy2.2.6、ml_dtypes0.6.0。实际可见逻辑设备1个、使用0。`runtime_identity.json`保留版本、加载库SHA、allocator快照及npu-smi原始输出。未调整时钟/全局设备策略。

以下变量在全新shell按实际目录设置，先激活上述Python依赖环境。`PYTORCH_NPU_ALLOC_CONF`必须在Python导入torch之前设置；custom及baseline完全相同。未设该项的旧试验不能支持本包性能结论。

```bash
set -euo pipefail
export SUBMISSION=/absolute/path/to/task_submission
export REPO_ROOT=/absolute/path/to/xllm-source
export OP_ROOT="$REPO_ROOT/xllm/core/kernels/npu/xllm_ops/t5_split_qkv_append_cache"
export TASK_PACKAGE="$SUBMISSION/6 自测用例及测试代码/官方任务包"
export RUN_ROOT=/absolute/path/to/new-t5qkv-run
export T5QKV_INSTALL_PREFIX="$RUN_ROOT/install"
export T5QKV_REPORTS="$RUN_ROOT/reports"
export T5QKV_SOLUTION="$OP_ROOT/solution.py"
mkdir -p "$T5QKV_REPORTS"
source /usr/local/Ascend/ascend-toolkit/set_env.sh
export ASCEND_RT_VISIBLE_DEVICES=0
export PYTORCH_NPU_ALLOC_CONF=page_size:1g
unset TASK_QUEUE_ENABLE ASCEND_LAUNCH_BLOCKING
```

官方allocator选项依据：[Ascend PyTorch内存管理文档](https://github.com/Ascend/pytorch/blob/master/docs/zh/api/environment_variable/memory_management/PYTORCH_NPU_ALLOC_CONF.md)。大池按1GiB级预留，对进程内存占用有影响；本次实测快照另有2MiB小池。显式workspace仍为0，保留池不等于泄漏或workspace。升级OS/driver/CANN/framework或allocator配置均应重新验证。
