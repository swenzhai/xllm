## 获取固定版本并构建

在具备指定CANN/Python/torch_npu依赖的目标服务器上执行。仓库需当前账号有访问权限，SSH方式使用已有key；交付路径和新工作目录应按实际修改。

```bash
set -euo pipefail
export SUBMISSION=/absolute/path/to/task_submission
git clone --branch t5-qkv-task-submission git@github.com:swenzhai/xllm.git /absolute/path/to/xllm-source
git -C /absolute/path/to/xllm-source checkout --detach ab70af7891455b36c7aaac6344f0f2207afcc068
export REPO_ROOT=/absolute/path/to/xllm-source
export OP_ROOT="$REPO_ROOT/xllm/core/kernels/npu/xllm_ops/t5_split_qkv_append_cache"
export TASK_PACKAGE="$SUBMISSION/6 自测用例及测试代码/官方任务包"
export RUN_ROOT=/absolute/path/to/new-t5qkv-run
export T5QKV_INSTALL_PREFIX="$RUN_ROOT/install"
export T5QKV_REPORTS="$RUN_ROOT/reports"
export T5QKV_SOLUTION="$OP_ROOT/solution.py"
mkdir -p "$T5QKV_REPORTS"
source /usr/local/Ascend/ascend-toolkit/set_env.sh
# 激活与步骤说明匹配的Python/torch_npu环境后继续。
cd "$OP_ROOT"
export T5QKV_BUILD_DIR="$(mktemp -d "$OP_ROOT/build.acceptance.XXXXXX")"
export T5QKV_BUILD_JOBS=2
bash scripts/build.sh
PACKAGE_RUN="$(find "$T5QKV_BUILD_DIR" -maxdepth 2 -name '*.run' -print -quit)"
test -n "$PACKAGE_RUN"
bash scripts/install.sh "$PACKAGE_RUN" "$T5QKV_INSTALL_PREFIX"
source "$T5QKV_INSTALL_PREFIX/vendors/t5qkv/bin/set_env.bash"
export T5QKV_OPAPI_LIB="$T5QKV_INSTALL_PREFIX/vendors/t5qkv/op_api/lib/libcust_opapi.so"
export MAX_JOBS=2
bash scripts/build_framework.sh
cmake -S examples -B "$RUN_ROOT/build_example" -DT5QKV_OPP_PATH="$T5QKV_INSTALL_PREFIX/vendors/t5qkv"
cmake --build "$RUN_ROOT/build_example"
"$RUN_ROOT/build_example/t5qkv_aclnn_example"
```

全部日志采集、35个精度case、扩展工程检查、10个性能/内存case的预热/轮数/检查器命令见根目录 `1 自验证步骤说明.md`。不能只运行本索引的构建命令就认为验证完成。完整xLLM服务构建与端到端验证尚未执行；native wrapper证据限于实际宏下的语法/类型编译。

## 两阶段API与构建产物

API头由CANN构建流程生成并由 `.run` 安装至 `$T5QKV_INSTALL_PREFIX/vendors/t5qkv/op_api/include/aclnn_t5_split_qkv_append_cache.h`；对应动态库位于 `op_api/lib/libcust_opapi.so`。该生成文件不冒充Git源文件，生成规则/原型依据是OpDef和C++样例。

第一阶段 `aclnnT5SplitQkvAppendCacheGetWorkspaceSize` 查询workspace并产生executor，第二阶段 `aclnnT5SplitQkvAppendCache` 接收workspace、executor与stream执行。当前合法输入workspace为0。完整输入输出与属性原型见设计文档2.3.1。Python `run` 走ACLNN，`run_direct` 用直调做交叉验证，`prepare` 保存校验元数据；正式性能入口为 `run`。

本目录 `custom_opp_ubuntu_aarch64.run` 是冻结证据中的同一安装包，SHA256：`8326e307a751ab75664316e5a7980cdd2817c901ec15c43ea4edf30cfa94f33b`，大小 223669 B。它来自Ubuntu 22.04.5 / aarch64 / CANN 9.1.0的开发构建；在指定openEuler/driver环境必须重新构建并复测。本次整理未运行安装包。若在兼容开发环境重现旧产物，使用 `bash "$OP_ROOT/scripts/install.sh" "$SUBMISSION/7 待验收工程/custom_opp_ubuntu_aarch64.run" "$T5QKV_INSTALL_PREFIX"` 安装至独立用户前缀。

原始direct/framework SO保留在冻结服务器tar中，跨环境复现应按源码重建。原始源码指纹、加载库身份、构建/安装/样例日志见根目录 `5 原始证据.zip` 中的manifest及reports；验收证据的限制见交付清单。
