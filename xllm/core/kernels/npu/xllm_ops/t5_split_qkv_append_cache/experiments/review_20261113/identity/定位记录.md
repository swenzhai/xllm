# 默认分配器超限定位（2026-11-14）

当前性能问题未关闭，XLSX及旧交付ZIP未改。以下是诊断，不是验收通过报告。

旧/新28份产品源码相同；SDK两种dtype内核、opapi和direct库整文件SHA相同。extension的.text相同，.init、动态链接及debug/build-id节不同，不能说整个extension相同。8个精度进程各35/35，24个原协议完整10项交叉进程全部完成，加载库核对且前后manifest一致。PID逐一确认visible0/1对应NPU3/chip0/1、physical6/7、PCIe91/93。旧硬件PCIe99/9B不可直接访问。

这些计数/时间来自同一个插桩进程，只作诊断；不能当通用命中率或替代原24批未加循环hook的结果。两芯片默认虚拟地址相同但事件数不同，仅看虚拟地址不能解释性能。默认为四个66MiB大segment，1g为一个1GiB大segment；默认大buffer低21位全零，1g有1024/1536/2048/35328偏移。

只读aclrtPointerGetAttributes在两芯片/两配置共24个buffer均成功，pageSize raw均为2097152。该环境API报告的页大小均2MiB，不能将收益解释成物理页从2MiB变为1GiB。隔离页probe不等于先前benchmark分配历史，也不拼接为同进程计数。

证据将瓶颈定位到与分配段布局/物理设备映射相关的L2驻留或访问退化。新机器码、所捕获进程中的输出地址漂移、1GiB物理页三种解释不受支持；具体cache set/hash、物理页颜色及TLB剩余贡献尚未证明。

C6/C7仅改变Key输出独立存储余量的前/尾放置。18功能子检查全部通过，含各配置206工程/10内存/8cache boundary；18批性能完成且前后manifest一致，默认仍失败，1g通过。单独2KiB偏移没有闭合问题，两候选淘汰。附属kernel_identity.json末尾误写了字面反斜杠n，原件保留，派生索引只解析完整JSON对象并记录该限制；原始测试报告/日志均为有效JSON且未修改。

C8按每核16个Value历史tile中前15个正常缓存、最后1个旁路重新分布，其他几何仍用原prefix。正常/旁路60MiB/4MiB、52字节POD、184KiB双槽、内循环/事件顺序不变。CPU实际helper证明768任务唯一覆盖、256追加和字节数不变。新增8项row-tagged uint16边界，避免重复行模式漏检。该方案不同于历史被否定的172/176MiB Key输出条带方案；C8正在真实验证，尚无性能通过结论。
