# 默认分配器超限定位（2026-11-14）

当前性能问题未关闭，XLSX及旧交付ZIP未改。以下是诊断，不是验收通过报告。

最新实测已确认底层分配策略差异：默认及外部预留1GiB均调用`aclrtMallocAlign32(..., ACL_MEM_MALLOC_HUGE_FIRST=0)`；`page_size:1g`的大段调用`ACL_MEM_MALLOC_HUGE1G_ONLY=6`，两芯片实际调用均成功。相同虚拟地址、相同1GiB segment不能说明底层分配等价。该差异与同进程L2计数/耗时差异相符，但物理页地址、连续性及L2 hash未独立测得，不能宣称唯一硬件冲突机制已经证明。C18默认性能仍失败，未晋升。

## 本轮完整结论及停止点

C18采用C4准入策略、无额外GM，将大输出平铺成1427个连续写tile；读取2448个piece，正常/旁路边界及各写块起止512B对齐，其他几何回退原C4。实际CPU helper逐元素验证67141632元素完整覆盖。A3构建完成、functional_02的18子检查全部通过（两配置35精度/206工程含10内存及边界/非对齐输出guard）；初次functional_01因驱动多传一个参数在supplied_outputs解析阶段失败，原目录保留，新runner02完整复跑，不覆盖原件。

原完整10项50/200/5协议12批全部完成、post-identity每进程五库核验通过且无error，前后source/artifacts不变。C18默认007三批91.687/91.511/98.718µs（上限75），017三批112.904/92.138/89.617µs（上限77），全部未达标；1g两大case三批约69.894–70.427µs。对照C0默认本轮约85.5–86.7µs，不能沿用上一轮control约159µs计算收益；C18默认在本轮没有改善，不晋升。初筛失败，因此未执行20进程确认/full回归/交付更新。

随后6个同进程history诊断（default、default外部预留1GiB-512B、page1g，各双芯片）完整核对31556次alloc/全部原10项顺序；原始trace均未截断，前后manifest一致。**预留default与page1g在每个芯片上，007和017的全部输入、输出绝对虚拟地址都完全相同**，大segment同为0x12c180000000起始1GiB；每个case1000次timed调用只有一个输出地址三元组。该插桩诊断中，physical6预留default约114µs而page1g约72µs；physical7约83µs与72µs。不能把这些插桩值当验收，但它进一步排除了“仅靠虚拟起址/段内偏移相同就能复现1g收益”的充分性，须区分物理后备、分配策略和未观测设备状态。此前12进程预留实验有改善也有退化，不能挑快批替代全部结果。

API pageSize=2097152仅是所用查询接口的报告值。它没有暴露HBM物理地址、连续性、页颜色或L2 set/hash；不能将其扩展成“所有底层物理分配属性相同”，也不能据此彻底排除不同物理分配策略的影响。当前证据支持分配策略/物理后备敏感的缓存访问退化，不支持唯一cache冲突机制已被证明。

本轮已完成机器码交叉、双芯片映射、同进程地址/L2、API页属性、外部pool干预和输出准入/连续写优化。按C18既定停止条件，停止相同缓存预算/输出排列方向盲扫；下一步应先核对安装版本分配实现的实际ACL分配policy及物理映射证据，再决定新内核方案。未调整阈值/用例/原协议/全局allocator，未将dummy预留加入生产入口，默认产品及三份XLSX、旧交付ZIP不变，007/017性能问题仍未关闭。

## 实际ACL分配策略（追加实测）

安装的torch_npu 2.10.0.post4记录git_version `5dd8ef3f9b375b5ae4a83538d5785754148c3302`。本地未安装allocator .cpp实现且libtorch_npu内部符号已剥离；因此没有根据字符串猜测执行分支，而是使用独立LD_PRELOAD诊断工具透传原API参数和返回值，拦截显式dlsym及动态绑定的aclrtMalloc/aclrtMallocAlign32/aclrtMallocPhysical。仅隔离分配六个同形状Tensor并查询属性，没有运行算子或benchmark，没有将插桩计时当验收。

| 两芯片各自实测 | 大segment大小 | 实际aclrtMallocAlign32 policy | 返回码 |
| --- | ---: | --- | ---: |
| 默认 | 4×66MiB | HUGE_FIRST(0) | 全0 |
| 默认，外部allocate/free(1GiB-512B) | 1GiB | HUGE_FIRST(0) | 全0 |
| page_size:1g | 1GiB | HUGE1G_ONLY(6) | 全0 |

小2MiB segment在三模式都使用policy0。每个API返回指针已与该进程allocator snapshot的segment基址逐项对应，两芯片共六进程完整通过，前后source/header/interposer SHA不变。`acl_rt.h`原枚举片段和torch_npu版本、库SHA、构建命令、每次真实分配参数/返回值、36个属性查询和原日志全部归档。36次属性查询仍全部报告2097152，故**早期仅凭pageSize=2MiB否认1GiB分配路径的推断已修正**：实际policy6路径成功发生，但具体物理页连续性/cache颜色仍未被独立测量。

结合此前无插桩原协议交叉、同进程地址/L2和完全相同绝对VA的pool-history证据，可以确认默认与1g不只是段内偏移差别，底层ACL策略确实不同；这是当前缓存退化定位的关键进展。不能把隔离API跟踪与另一个进程的计数冒充同一次因果测量，也不能据此宣称已证明某个硬件hash。后续优化应先针对HUGE_FIRST的实际缓存访问行为设计方案，不再用外部大段预留冒充等价的1g配置。当前不改生产allocator、不修改任务门槛。
